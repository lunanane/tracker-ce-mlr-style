# Plan 005 — v0.2 rework after first hardware test (2026-11-04)

Owner tested v0.1 on the original Tracker: "kinda working", but needs rework on all ends.
Hardware note from the owner: the button we called "Pattern" is labelled as a second
**Perform** button on their unit. Play mode (double tap of that button) stays where it is.
Owner's naming (confirmed): **sequencers = bottom-right "Perform" (firmware: Pattern)**,
**FX faders = top-row "Perform" (firmware: Performance)**.

## R1 — Play mode (Pattern double tap) redesign

- The normal tracker (pattern) view stays on screen. Only the **lower section** of the screen
  shows the sequencer settings of 8 tracks (one slot per screen button).
- Left/Right switch that lower row between tracks 1–8 and 9–16.
- Pressing a screen button selects that track and highlights it in the pattern view above.
  If the track is not on screen, the view brings it in (what stock does manually with
  Left/Right). The pattern view pages in **blocks of four tracks**: selecting a track switches
  to the block of four that contains it and highlights it there.
- Sequencer type: **hold the track's screen button + wheel** (replaces Instrument + wheel).
- While a script is dialled in / played: **holding Shift** shows a mini-map legend of what the
  pad fields do, drawn above the standard mutes.

## R2 — Alt Song mode = clip launcher (Song double tap)

- Song double tap toggles alt Song mode (the clip launcher; already works in v0.1).
- The Song screen draws a **rectangle around the 8×4 area** the pads currently control.
- Arrow keys move the rectangle: Left/Right jump between tracks 1–8 and 9–16, Up/Down move
  through the rows.
- Pads: columns 1–8 = clips of the 8 tracks in the rectangle, **column 9 empty** (visual gap),
  **column 10 = scene launch** for that row, columns 11–12 empty.
- **Default playback = loop** for clips and scenes. Holding screen button 1 (where Loop sits)
  + wheel sets a clip's play mode. Modes for now: **Loop**, **Play 1x**.
  Shift + screen button 1 sets the mode for the whole scene.
- Play 1x follow action: when the clip has played once, **launch the clip in the next row down**.
- CUT/MLR layer: unchanged unless the owner says otherwise (open point).

## R3 — Fader page (alt Performance)

- Owner: the faders "work great". But stock Performance already uses a double tap (to switch
  between tracks), so the fader page moves to **Shift + Performance**.
- Fader settings **and fader positions persist** (saved with the project).
- Remove the "reset to default" column. Instead, the **last column** disengages (bypasses)
  the effect of that particular fader row — useful for builds.
- Much better visualisation: sections clearly drawn, and you see which FX are active and how
  they are set.

## R4 — MLR (CUT) screen

- New interface for MLR mode: the tracks are shown **horizontally** (one lane per track) with
  each track's **playhead position** visible, MLR style (a lane per pad row).
- **Easy way out**: one action snaps all tracks out of MLR loops / jammed positions and syncs them
  back to the global playhead (sketch: screen button 7 SYNC ALL + Shift + any RESYNC pad).

### 2. R1 — Play mode inside the pattern editor

**Stock facts.** `cTracker` (`tracker.cpp:307-330`): the full view (`patternViewMode == 0`) shows **4 track
columns** of 200 px. The single-parameter view (Pattern held + Note/Instr/FX1/FX2, modes 1–4) shows **8 columns**
of 100 px. There are 15 rows: 26 px each with the title bar (y 28–423), 28 px each with `patternInfo` (y 0–423)
(`gPatternEdit.cpp:229-236`). The original Tracker has 16 tracks (8 sample + 8 MIDI, `mtStructs.h:87-103`).
Left/Right move the **cursor by one track** (`previousTrack/nextTrack` `fPatternEdit.cpp:~2335-2462`), and the
window follows with `focusOnActual()` (`:952-967`). That is a **sliding window, not blocks of four**: with the
cursor on track 5 the view shows tracks 2–5. The playhead/cursor row is row 7 of 15 (`actualStep - 6 + i`).
Stock mutes: pressing Shift (`functShift` `:2110-2114`) calls `showMuteButtons`, which rewrites the 8 bottom labels
as "name / Mute|Unmute" (`gPatternEdit.cpp:1167-1205`). `setMuteFunct` binds the screen buttons to mute the sample
tracks or the MIDI tracks, depending on the cursor track. Releasing Shift calls `refreshEditState()`, which rebinds
them.

**Design: Play mode becomes a 4th action-button page of `cPatternEditor`, not a separate module.** The editor
already has 3 action-button pages (`actualActionButtonsPage`, `patternEditor.h:352-353`, switched in
`refreshActualActionButtonPage()` `fPatternEdit.cpp:5211-5236`). Every stock label writer already returns early
when `actualActionButtonsPage != 0` (`showPattern/showLength/showStep`, `gPatternEdit.cpp:349,409,427`).
Play mode therefore sets `actualActionButtonsPage = kSeqPlayPage (3)`:
- The pattern view, playhead follow, title bar, mutes, Shift, Up/Down and Play keep running unchanged.
- The bottom labels belong to the overlay.
- `refreshEditState()` (after Shift, popups etc.) rebinds the page automatically through the new `case 3`.

`cSeqPlay` stops being a `ModuleBase` and becomes a helper (`seqPlayOverlay`) that the editor calls.
`eventActivateSeqPlay` is dropped.

Hooks (all small):
- `functPattern` (`fPatternEdit.cpp:2882-2911`): a tap toggles the page. Entering forces `editMode = 0` so Rec is
  free, and remembers the previous page. Leaving returns to page 0. The Play → Session step is removed (Session
  moves to Song, see R2).
- `refreshActualActionButtonPage()` `case 3`: bind screen buttons 0–7 to `seqPlaySlotButton(button, state)` and
  write the 8 two-line labels.
- `lightUpPadBoard()`: `return` while the page is 3. It runs on every playhead step (`fPatternEdit.cpp:~298`) and
  would otherwise overwrite the sequencer LEDs.
- `cPatternEditor::update()`: call `seqPlayOverlay.update()` (LEDs every 30 ms, labels when they change).
- `start()`: a module start resets page 3 to 0. `stop()`: `seqPlayOverlay.leave()`, which ends a recording and
  releases the pads (what `cSeqPlay::stop` does now).
- **Input router** in `interfaceInputs.cpp` (already our file). While the page is 3 and the editor is on screen:
  - pads → sequencer;
  - Left/Right → strip 1–8 / 9–16;
  - Rec → sequencer Rec (Shift + Rec = one loop, as in v0.1);
  - jog **while a screen button is held** → type list; otherwise the stock jog;
  - Note / Instr / FX1 / FX2 / Copy / Insert / Delete are swallowed (no popups, no edits over the strip).

  Everything else passes through. One routing point; no guards spread through `fPatternEdit.cpp`.

**Screen buttons: tap vs hold needs no timing.**
- *Press* selects the track at once: `actualTrack = t`, `firstVisibleTrack = (t / cols) * cols` with
  `cols = patternViewMode ? 8 : 4` (the owner's "blocks of four"), then `refreshPattern()`. Check on the device that
  the cursor frame is drawn when edit mode is off; if not, set `selectState = 1`.
- *Turning the wheel while held* opens the type list in that cell (`seqlogic::stepTypeSelection`).
- *Release* applies the choice if the list was opened: at the next bar while playing (v0.1 `postType`).

With Shift held, the screen buttons are the stock mute buttons (stock code, untouched).

**Regions** (title bar on; with `patternInfo` everything moves up 28 px and rows are 28 px):
```
y   0- 28  title bar (stock)
y  28-423  pattern, 15 rows x 26 px; playhead row = row 7 (y 184-210), never covered
y 330-422  transient: type list (3 boxes 98x30 above the held cell, x = cell*100+1) or, while Shift is held,
           the pad legend (one custom control, 12 x 4 cells of 60 x 22 px, x 40-760, y 334-422)
y 424-479  strip = the 8 bottom labels (two lines, Font3): "6 MONO*" / "live", "2 CHRD" / "next: Off",
           "3 ---" / "pattern"; the selected track in brackets / active colour; REC = red label colours
```
- The pattern does not need to lose rows. The strip uses the label row, and the legend and type list are temporary
  overlays. (There is a precedent for shrinking: the fill popup sets `popupMode |= 1` for 8 rows,
  `tracker.cpp:325`. We do not need it.)
- Legend content per type comes from the plan 001 layouts:
  - Chord/Arp: 24 root names, the 4×4 PANEL, TYPES SET GRV PRM INV± OCT±.
  - Mono: steps 1–8, HALF PG± CLR TIE SPD± WIN± LOOP.
- A per-track "key setting" line (chord name, mono step) needs a new read-only accessor on `seqtracks::Engine`. The
  main loop reads it, and a torn value is acceptable for display. This is optional: v0.2 can show only the type and
  the state.

### 3. R2 — alt Song mode = clip launcher

**Stock Song page.** `cSongPlayer` (`songPlayer.cpp`) sits at x 1, y 29, w 697, h 394:
- **16 track columns** of 26 px with 4 px spacing (`TOTAL_BLOCKS_WIDTH 486`, `:8-17`);
- **12 song rows** of 23 + 4 px from y 93 (`:715`);
- track names written vertically in y 29–93, the slot list on the right (x 487–697), the tempo bar at x 701–798.

Rows are **song slots** (`mtProject.song.playlist[]`, 255 entries; the length is the position of the first 0,
`fSongEdit.cpp:973-985`). A block is lit when that slot's pattern has notes on that track: sample tracks from
`mtProject.values.allPatternsBitmask[p-1]`, MIDI tracks from `…BitmaskMidi[p-1]`, kept current by
`updatePatternBitmask` (`fileManagerSong.cpp:194`). The page already draws a **selection rectangle**
(`song_selection_t`, `calculateSelection/drawSelection` `:812-889`).

The Song button on the Song page (`functSwitchModeSong` `fSongEdit.cpp:1445-1484`): a press focuses the slot list
until release; a hold is momentary (the page is left on release). A tap therefore has no lasting stock effect and is
free for the toggle.

**Entry.** A Song tap on the Song page opens the clip launcher (`eventActivateSeqSession`). The tap uses a new
`seqSongTap` (same `TapDetector`), armed on the press in `functSwitchModeSong` and checked on release only when
`exitOnButtonRelease == 0`. In the launcher a Song press returns to the stock Song page. The
Pattern → Play → Session cycle is removed (R1 owns that line).

**Screen.** `cSongPlayer` cannot draw the sketch: it only draws blocks, with no gap, no scene column and no glyphs.
Use a custom `cSeqClipGrid` control in the session module, x 0–800, y 29–422:
- header y 30–66 with the track numbers;
- row numbers x 4–40;
- 16 cells of 30 × 23 px, with a 4 px gap after track 8 (x 44–528);
- a 20 px gap, then the scene cell at x 548–588;
- an info column at x 600–796: quantise, countdown, now/next per track of the window, play mode of the focused cell;
- rows of 27 px, 12 visible rows at y 70–394.

16 tracks fit easily. The pad window is a 2 px red rectangle, as in stock `drawSelection`. Cell states as shapes:
- empty: dark;
- has notes: mid grey;
- playing: bright, plus a 3 px progress bar (position / clip length);
- queued: blinking outline;
- Play 1×: a small notch in the top-right corner.

Redraw on events, and at most once per step while a clip plays (for the progress bar).

**Mapping.**
- Rows = song slots (v0.1's `Window` used pattern numbers 1–255).
- Clip (track t, slot s) = track t of pattern `playlist[s]`.
- Window = 8 tracks (`first` 0 or 8) × 4 slots (`top`).
- Left/Right = tracks 1–8 / 9–16. Up/Down = one slot (Shift = 4). Jog = one slot. Clamped to `0 … songLength-4`.
- Pads: columns 1–8 are clips, column 10 launches the scene, the rest do nothing (`mapPad` in
  `seqSessionLogic.h`: col 0–7 CLIP, col 9 SCENE, others NONE). An empty clip pad stops the track (v0.1 rule).
- STOP-T / STOP-A / QUANT lose their pads and move to screen buttons (provisional, see open questions):
  - 1 = MODE (hold);
  - 2 = QUANT (each tap cycles);
  - 3 = STOP (hold + clip pad = stop that track, hold + scene pad = stop all);
  - 8 = CUT layer.
- "Has notes" comes from the bitmasks above, so `NoteCache`/`scanOneRow` (SD reads, `seqLauncher.cpp:122-150`) can go.

**Play modes.**
- The focused clip is the last clip pad pressed (framed in the grid).
- While screen button 1 is held, pads only focus a clip; they never launch, so there are no accidental launches.
- Wheel (button 1 held) = Loop ↔ Play 1× for the focused clip.
- Shift + hold 1 + wheel = the play mode of the focused row's scene.

Storage is keyed by **pattern × track**, so it survives slots being inserted or deleted in the stock Song editor:
2 bits × 255 × 16 = 1020 B, plus 2 bits × 255 = 64 B for scenes. It is saved in a sidecar `seqclips.bin` (same
format as R3's).

**Follow action (Play 1×), audio side.** Today `Launcher` has one global quantise (`quant_`) and launches in
`onStep(t, pos)` at the track's step boundary (`seqLauncher.cpp:209-224`, `quantHit` `seqSessionLogic.h`). Add:
- a per-track command quantise `q_[t]` (one more byte in `Cmd`) with a new value `Q_CLIPEND`;
- a per-track step counter `since_[t]`, reset in `apply()` and incremented in `onStep`. `Q_CLIPEND` hits when
  `since_[t] > 0 && since_[t] % clipLen == 0`, with `clipLen = player.performance.trackLength[t] + 1` passed in by
  `Sequencer::seqSessionStep`. It counts steps, not positions, so CUT jumps and rate changes do not confuse it;
- a per-track `applied_[t]` counter that the main loop can read.

**Main loop** (`seqSessionUpdate`): when `applied_[t]` changes and the clip is Play 1×, take slot `s+1`.
- If `s+1` is beyond `songLength` or track t has no notes there: `postStop(t, Q_CLIPEND)`.
- Otherwise: `loadClipTrackToBuffer(playlist[s+1], t)` + `postClip(t, …, Q_CLIPEND)`.

Timing safety:
- The load has one whole clip length of time.
- If the file manager is busy, the main loop retries on every pass. While `loading_` is set the launcher waits for
  the next clip end: the 1× clip plays once more. There is never silence and never a switch in the middle of a step.
- This is safe because the track's slot in the performance buffer was already copied into the pattern when the
  current clip was applied.

Scenes on Play 1×: after `seqSessionPatternSwitched` with a 1× scene, the main loop queues
`seqSessionLaunchScene(playlist[s+1])`. That is the stock `sequencialSwitch`, which fires at the pattern end, so it
has a whole pattern of time. A user tap on that track or scene cancels the pending follow action (the existing rule:
the newest tap wins).

**CUT/MLR** is layer 2 of the same module (`fSeqSession.cpp`, `kButtonCut = 7`). R2 does not conflict with it
functionally: a Session STOP still wins, and a launch still calls `Cut::launched`. But R2 and R4 share the module's
screen code (see §7).

### 4. R3 — fader page

**Stock double tap.** Stock has **no** double tap: every Performance press flips the tracks page
(`fPerformance.cpp:661-683`; stock binding `buttonPress → functSwitchTracksPage`). Our v0.1 hook adds a 350 ms
window for a second tap (`:684-731`). Two quick presses (flip and flip back, the owner's "double tap to switch
tracks") therefore land the user on the fader page. Fix: restore the stock binding exactly (one line) and delete
`tapPending/tapAge`.

**Shift + Performance.**
- **On the stock page**: in the Performance press handler, Shift held → open the fader page without flipping. This
  replaces the stock "flip while in mute view" combination; flipping without Shift still works.
- **From any other module**: in `Interface::switchModuleByButton`, if the button is Performance and Shift is
  physically held, activate `seqPerform`. The check must run before `deactivateModule`, which fakes a Shift release
  (`interface.cpp:431`). `cSeqPerform::start` must then do what `cPerformanceMode::start` does when nothing was
  handed over: `readPerfData`, all track states 0, `loadSelectedValuesToTempValues` (`fPerformance.cpp:81-130`).
- **On the fader page**: a Performance press returns to the stock page (as now, but on the press, without tap
  logic).

**Persistence.** A sidecar `seqperf.bin` next to `seqtracks.bin`.
- Payload (≈ 64 B): magic "SQPF", version 1, page, `fxStep[3][4]`, `sendStep[2]`, `latch[5][4]` (bits), bypass
  bits, a snapshot of the 12 slot FX ids, CRC16. The FX ids are those of the active source (`perfFxPlaces`); the
  slots can come from the global config, not the project (`performanceDataSource` `performanceEngine.cpp:24-46`).
- On load, a position whose slot FX id differs from the saved one is dropped.
- Positions only matter for latched faders; momentary faders snap back anyway.
- Latched faders come back when the fader page is entered (`reapplyActive`). As on stock, the FX end when the user
  leaves for a page that does not keep them (`stop()` → `performance.turnOff()`, `fSeqPerform.cpp:116-128`).
- `start()` must no longer `memset` the state (`:85-105`).
- Hook points are the four that `seqtracks.bin` uses: `ProjectSave.cpp:544`, `WorkspaceProjectLoad.cpp:166`,
  `WorkspaceProjectSave.cpp:122`, `ProjectOpen.cpp:367`.
- Writing works like `seqTracks.cpp:414-474, 590-680`: write `.tmp`, then remove the old file and rename. A hash is
  compared about once a second to detect changes, and a failed write is retried. A project that never used the page
  gets no file.
- A missing or short file, a bad CRC or a newer version → defaults. A sidecar never blocks a project load.
- R2's `seqclips.bin` uses the same scheme. Both share the one `s_io` buffer (EXTERNAL_RAM, 2810 B). The
  write/read helpers are first factored out of `seqTracks.cpp` (step 0).

**Reset column → bypass.** The owner's wording is ambiguous: "the last column (three buttons under the fader pages)
to disengage the effects in that particular row".
- **(A)** Column 12, rows 1–4: bypass fader row r of the current page. Four pads. It matches "row", the lead's
  default and the ON/BYPASS cell of the UX sketch.
- **(B)** Column 12, rows 1–3: bypass a whole group (FX1-4 / FX5-8 / FX9-12), next to the three group pads in
  column 9. It matches "three" and "fader pages".

**Proposal: (A)**, with the state kept per page × row (20 bits). Behaviour:
- Bypass on, FX rows: the slot is released. Send rows: the send goes to 0. PING/REV rows 2–4 hold project values,
  so bypass restores the value from before the fader was used and puts the fader value back on un-bypass.
- The fader position and LATCH are kept; the LEDs dim.
- Pressing a fader while it is bypassed moves the stored position silently ("pre-arm for the drop").
- Un-bypass re-applies at once.
- RESET disappears. LATCH off + release still returns a row to neutral.

**Visualisation.** One custom control `cSeqFaderView` with 2 stages. The bottom labels keep their meaning: the
tracks the FX and sends affect.

### 5. R4 — CUT/MLR lane screen

**Today.** CUT draws nothing of its own. `CutSessionLayer::info()` returns four text lines
(`cutSessionLayer.h:25-31`), which the module prints (`fSeqSession.cpp:222-235`). The LEDs come from `Cut::view()`
(`seqCut.cpp:101-111`): the playhead column 0–7, the loop range, and flags for STOP / REV / REC / RECORDED / rate
(`seqCutLogic.h:90-106`). A track that is not cut-active reports column 0.

**Reading positions cheaply.** `Sequencer::seqTrackPos(t, pos, uStep, last)` (`seqTracks.cpp:345`, public,
`mtSequencer.h:774`) does aligned 16-bit reads of `actual_pos`, `uStep` (1–48) and the track length. It is safe on
the main loop; a torn pair costs one frame at most. It works for stock and cut tracks alike, because cut tracks
write `actual_pos`. The grid ghost (where the track would be without jamming) is the shadow stock position
`seqCutStockPos(t)` (`mtSequencer.h:783`). A resolution of 1/48 step is smooth enough. The sketch's "true 16-bit
position" (the sample offset) is not available on the main loop and is not needed.

**Lanes = pad rows = 4** (a CUT group is 4 tracks, `groupSize() 4`). 16 lanes would not match the pads.
```
y 29- 66  header: "CUT 5-8"   REC state   bar.beat (from globalPos)
y 70-400  4 lanes x 82 px:  x 4-96 track number + name (Font3), flags (STOP/REV/rate/REC as text/shapes)
          x 100-700 lane: 8 segments of 75 px (= pad cols 1-8), step ticks (<= 128 steps -> >= 4.7 px),
          note marks (seqCutNoteMap, computed when the group or pattern changes, not per frame), loop bracket,
          playhead 3 px bar, grid ghost 2 px tick;  x 704-796 4 cells mirroring pad cols 9-12
y424      bottom: 1-4 | 5-8 | 9-12 | 13-16 | | | | CLIPS
```
**Redraw cost.** A refresh regenerates a control's whole display list, so the view is split into two controls:
- `cSeqLanes`, the static part (segments, ticks, notes, flags), redrawn on events;
- `cSeqPlayheads` (4 bars + 4 ticks, ~40 display-list words), redrawn when any position changed, at most 25 fps.

On MK66 the main loop also refills the SD streams, and plan 002 noted that redraw stalls can be heard. Measure; if
streaming underruns, fall back to one redraw per step.

**SYNC ALL (owner: one way out of MLR).** Triggered by screen button 7 in the CUT layer, or by Shift + any RESYNC
pad (column 12).

How the existing per-track paths work:
- `SUB_RESYNC` (`seqCut.cpp:129,170`) only sets `r.resync`. At the track's next step boundary `Cut::boundary`
  (`:217-226`) calls `Playhead::resync(globalPos)`, which clears the loop, the queue and the recording.
- The track goes back to the stock sequencer **only if it is then plain** (`isPlain`: rate 1, forward, nothing
  recorded or held; `:253`). Reverse and rate survive a RESYNC, so the track stays cut-active.
- `SUB_RESET` (`:115-119`, sent on project load) deactivates every track at once. But it leaves `actual_pos` at the
  jammed position, and after `deactivate` the shadow stock position is no longer restored (`seqCutPreSwitch`,
  `seqTracks.cpp:185-192`). The track would keep running offset, so RESET is not usable for SYNC ALL while playing.

Proposed: **one new command `SUB_SYNCALL`** (one ring entry; the track byte is ignored). It is applied in
`Cut::apply` inside one `drain()`, so it reaches all 16 tracks in the same audio block. For every active track it:
- releases the held columns (`r.held = 0`);
- sets `setRate(RATE_NORMAL)`, `setReverse(false)`, `clearRecording()`;
- sets `r.stopped = false` and `r.resync = true`.

At the next step boundary `seqCutApply` (one pass after all tracks have stepped, `seqTracks.cpp:219-237`) aligns
every track to `globalPos`. Each track is then plain and is deactivated, so the stock sequencer owns all of them again.
"Immediate" therefore means the next step boundary (≤ 1 step). That is the same point every CUT jump uses, and no
note is cut mid-step.

Why not 16 × `SUB_RESYNC`:
- the command ring (`kRing = 64`, `seqTracksCore.h:108`) is shared with the pad commands, and `postCut` drops a
  command when the ring is full;
- the 16 commands could be drained in different blocks;
- RESYNC does not reset reverse or rate.

Main-loop side (`cutLayer.cpp`): first end the local state, i.e. forget the held pads (`s_heldTrack`) and end Rec
takes (`s_recTracks`) without posting per-pad releases. Then post `SUB_SYNCALL`. If the ring is full, keep the
command pending and retry it on every pass, as `flushPending` does for releases (`cutLayer.cpp:36`), so the command
is never lost.

Not affected: Session STOP (a frozen track keeps its pending resync until it runs again) and launched clips.
Recorded playhead loops are discarded (they are not saved anyway). Host tests go in `core/seqtest` (test_cut):
SYNC ALL with mixed rate, reverse, loop and recording ends with every track inactive at `globalPos` after one
boundary.

## Devil's advocate

Checked against the `seq-tracks` working tree. Nothing was committed.

**What the spec gets right:**
- R1 as page 3 of the editor keeps the stock view, mutes and playhead running behind one router. That removes a whole
  module and a mode switch.
- "Press the mode's button again = back to stock" is the same in R1, R2 and R3.
- Song slots plus the stock bitmasks remove the SD scan.
- `SUB_SYNCALL` as one ring entry, applied in one `drain()`, is the right shape.
- The clip end is counted in steps, not positions, so it survives CUT jumps.

**Verdict: ship with changes.** Two findings break the core live workflow: launching clips, riding faders and playing
the song together. Both come from shared stock state, not from the new screens.

### Critical

**C1 — The faders and the launcher share the one `player.performanceMode` flag.**
- Launched clips live in the stock performance buffer (`seqSessionEnterPerformance`, `s_ownsPerf`,
  `seqLauncher.cpp:272-281`).
- `cSeqPerform::stop()` (`fSeqPerform.cpp:113-128`) calls `performance.turnOff()`. That runs
  `sequencer.exitPerformanceMode()`, `loadWorkspacePatternNow` and `switchRamPatternsNow`.
- It does this immediately, even while playing. Stock `functSwitchModule` waits for the pattern end with
  `turnOffAtEndOfPattern` (`fPerformance.cpp:648`).

*Scenario:* launch 3 clips in the launcher, press Shift+Perform, sweep the filter, press Song.
- All clips drop back to the pattern mid-bar.
- A pattern file is read from SD in the middle of playback.
- `s_ownsPerf` stays true and the grid still shows the clips playing.
- The reverse also happens: when the stock Performance page owns the flag, leaving that page ends the clips at the
  pattern end.

*Fix (spec):*
- Give performance mode an owner mask: `PERF_OWNER_LAUNCHER | PERF_OWNER_FX`.
- `turnOff` only resets the FX. It leaves performance mode only when no owner is left, and then calls
  `seqSessionPatternSwitched()` so the launcher state matches.
- Never turn off immediately while playing. Use `turnOffAtEndOfPattern`, as stock does.
- Host test: launch a clip, enter and leave the fader page. The clip and the launcher view still play.

**C2 — Song playback wipes launched clips at every pattern end.**
- `seqSessionPatternSwitched` runs on every pattern change, including when the song advances (`seqLauncher.cpp:253`).
- The launcher now sits on the Song page, where the performer naturally starts the song (`player.songMode`).

*Scenario:* the song plays and the performer launches a clip. The clip is gone 1–4 bars later, and that looks random.

*Fix:*
- Launching a clip or scene while `songMode` is on switches to the pattern loop at that launch point. Ableton does the
  same: launching overrides the arrangement. The header shows `LIVE` and the frozen slot.
- Screen button 4 = **BACK TO SONG**. At the next pattern end, all clips end and the song resumes at the slot after the
  playing one (Ableton's "Back to Arrangement").
- The grid marks the song playhead row with a bar on the left edge, in both states.

### Major

**M1 — Saved latched faders come back live, with an audible jump.**
- The investigation calls `reapplyActive` when the page is entered (§4).
- So the first Shift+Perform after loading the project, or after leaving the page, re-engages for example a latched
  stutter at its saved position.

*Fix:*
- Latched rows from `seqperf.bin` come back **bypassed and pre-armed**: position outlined, LEDs dim. The same applies on
  re-entry if C1 keeps the FX alive.
- The performer drops them in with the column-12 pad.
- Non-latched positions are kept but have no effect.

**M2 — SD work on the main loop during playback can cause late notes and stream underruns on MK66.** The sources are:
- (a) the pattern reload in the fader page's `stop()` (C1);
- (b) the change hash, checked about once a second. Fader positions change all the time in a set, so `seqperf.bin` and
  the project struct (`setProjectStructChanged`) would be rewritten about every second. Each write is a tmp write plus
  remove plus rename: several FAT block writes;
- (c) `seqTracksViewLeft()` → `autosaveProjectStruct_ASAP()` on every mode exit;
- (d) `loadClipTrackToBuffer` for Play 1×.

*Fix:*
- While `isPlay()`, sidecars and mode-exit autosaves only set a dirty flag. They are written on transport stop, on an
  explicit Save, or after 10 s without play.
- The fader hash covers the settings and the latched positions sampled on pad release, not the live values.
- Acceptance test: log the longest main-loop gap with `Profiler` while 8 sample tracks stream. For 5 minutes, toggle
  every mode, move faders and let Play 1× follow actions fire. The gap must stay below the stream buffer margin.

**M3 — Accidental type change on a live track (R1).**
- Hold a screen button + wheel; on release the type applies at the next bar.
- One detent nudged while pressing the button (the wheel sits next to the screen buttons) switches a running Chord
  track to Mono.

*Fix:*
- The first detent only opens the list, on the current type.
- Releasing with the selection equal to the current type does nothing.
- Leaving the page, or pressing Shift with the list open, cancels the list.
- Show `next: MONO` in the strip until the bar. The investigation already has this line. It makes a mistake visible
  before it lands.

**M4 — Mode taps fail silently while you play.**
- `seqNoteOtherInput()` (`seqTracks.h:14`) breaks a Pattern or Performance tap on any pad or jog input.
- `down()` also requires that no other button is held.
- A performer with one hand on the pads (arp, MLR) cannot reliably tap into Play or the launcher, or out again. Nothing
  shows that the tap was refused.

*Fix:*
- Only buttons break a tap. Pads and the jog wheel do not.
- Held pads do not block a tap; the leave rule (M5) releases them.
- Flash the title bar briefly when a tap is refused.
- Raise `kTapMaxMs` to 500 only if device tests show missed taps.

**M5 — No rule for what survives a mode change mid-performance.** Today each module tears down in its own way:
- Play releases the pads and ends the recording.
- Session `leave()` calls `cutReleaseAll()`, so every MLR loop stops even when you only switch to the clip layer to
  launch.
- The fader page turns the FX off (C1).

The spec adds Song↔Pattern↔Shift+Perform hops, so this rule decides how the set sounds.

*Fix:* add this table to the spec, with one host test per row.

| State | When you leave the view |
|---|---|
| held pad (chord, mono step, MLR cut, momentary fader) | released (note-off at the next step) |
| HOLD/latched arp, sequencer takeover, launched clips, queued launches, stopped tracks | **keep running** |
| CUT loops and jams on tracks, recorded playhead loops | **keep running** (only SYNC ALL or Stop end them) |
| seq recording (Rec) | ends at the next bar (one undo step), as in v0.1 |
| latched fader FX | keep running into the seq views (Play, launcher, CUT); stock rule elsewhere (Q6) |
| open type list / held-screen-button gesture | cancelled |

The CUT layer must not call `cutReleaseAll()` on a layer switch. On leave it only releases the held pads.

**M6 — No panic that works in every mode.** SYNC ALL exists only in CUT. Clips, takeovers and FX each need their own
exit.

*Fix:* document **transport Stop** as the panic for the mod.
- Stop already flushes launches (`seqSessionUpdate`).
- It also posts `SUB_SYNCALL`, ends recordings, and releases every held and latched pad.
- Faders keep their positions but switch to bypassed and pre-armed (as in M1).
- Stop then Play always gives the stock pattern playback.
- The fast exits per mode stay:
  - SYNC ALL in CUT;
  - hold STOP + scene pad in the launcher;
  - Shift + bypass pad on the faders (m5).

**M7 — The pattern view shows the wrong content while clips are launched (R1).**
- Page 3 draws the edit pattern.
- A track that plays a launched clip or an MLR jam sounds different from what is drawn.
- Rec on that track is refused (`seqRecTrackLaunched`).

*Fix:*
- The second line of the strip shows `clip P07` or `cut` for those tracks.
- That track's column header is drawn dimmed.
- No pattern redraw is needed.

### Minor
