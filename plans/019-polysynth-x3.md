# Plan 019 — one flexible PolySynth engine, three instances, Model:Samples-style multi-edit (owner 2026-11-06)

Owner: "The optimum for me would be to have 1 flexible synth engine and to be able to load 3 instances of it (in the
instrument list). Maybe extend our synth engine with some simple concepts, like 2 sub-octave square waves, some other
filter designs, and envelopes for them, more LFO waveforms … maybe borrow some concepts from the other synth engines as
well, so maybe a chorus also etc., to have a distinct sound but variations. Then since we have the same synth engine for
different instruments we can toggle between those and change parameters for one, but we can also hold Shift and dial a
parameter and then it adds the value to all other synth engine instances — basically the best performance workflow of
the Model:Samples."

## 0 — make room first (flash ~21 KB left, internal RAM 86 %, EXTERNAL_RAM 98 %)
Free flash (more -Os on control-rate audio code that isn't per-sample, dead code, data tables) and EXTERNAL_RAM
(SAMPLE_MEMORY_SIZE, developer guide) before adding features; keep the image < 0xF0000 with ≥ 16 KB margin.

### 0 as built (branch v039-room)
- **Flash limit corrected (coordinator, plan 018)**: the 0xF0000 rule came from a misreading; the working limit is now **image end < 0xFC000** (1,032,192 B), enforced by `platforms/mk66/check_image_size.sh` in the post-build step (prints end + margin, fails at the limit, warns below 16 KB margin). Keep the build lean anyway.
- **Freed 22,556 B of flash** (image end 0xEBFF8 = 961,912 B -> **0xE555C = 939,356 B**, margin to 0xFC000: **92,836 B**): (1) the whole MK66 platform (teensy core, FatFs, SDMMC, USB) at -Os except `3rdparty/Audio` (the I2S streams); (2) `effector` (offline sample editor), the seqgen generators (chordarp, mono, playhead), seqTracks / seqTracksCore / seqLauncher / seqSong / seqClips / seqCut / seqSidecar / scales and pad / keyboard / actions / mtTest at -Os (event-rate code, not per-sample; mtSequencer*, the audio engine, the DSP and seqFx stay -O2).
- **Word-wise memcpy / memset** (`platforms/mk66/source/fastmem.S`, own code): newlib-nano links byte loops (about 6 cycles per byte) and the Teensy `memcpy-armv7m.S` is empty in this build (assembled without -mcpu); every 256 byte block copy / clear in the audio interrupt gets several times faster (aligned path: ldm / stm, 16 bytes per loop; other alignments take the byte loop). tracker-ff's fastmem.S was NOT copied (provenance unclear). Not measured on hardware.
- **Not done, with reason**: the six double-to-float math call sites (sample-editor code, no CPU effect, small flash gain against 92 KB of room). **SAMPLE_MEMORY_SIZE is NOT reduced**: EXTERNAL_RAM is 98.27 % but 290 KB are free and plan 019 needs under 40 KB there (the chorus lines); lowering it would cut the resident sample pool (a project value, `max_memory`) for every user for nothing. If more is ever needed: 45 -> 41 * 256 KB frees 1 MB, see docs/developer_guide.md. Internal RAM unchanged (86.2 %); no big internal buffers are planned.
- Numbers: FLASH 934,796 B (89.15 %), RAM 225,976 B (86.20 %), EXTERNAL_RAM 16,486,232 B (98.27 %). Host: core/seqtest `make test` 0 failures (plinky 28,119 checks), seqgen 103,346 checks 0 failures.

## A — three instances
- Instrument list: **PolySynth 1 / 2 / 3** (three fixed slots, e.g. MIDI instruments 14/15/16 internally; v0.3.x
  projects with PolySynth on 16 keep it as instance 1 or as their slot — decide and migrate). Each instance: own
  parameters, own per-pattern snapshots + morph, own CPU readout share.
- **Shared voice pool + CPU governor** (concept from tracker-ff): e.g. 8 voices total across instances (max 4 per
  instance), steal by priority/age; a governor reduces voices when the audio block load gets high (measured), never
  glitches.
- PolySynth view (Play mode and Instrument page): **toggle between instances** with a clearly labelled key; the view
  shows which instance is edited. Pitch view per instance (colour per instance).
- **Shift + dial a parameter = relative change on ALL instances** (each keeps its own value, the same delta is added,
  clamped per instance) — the Model:Samples multi-edit. Clearly shown ("ALL" marker) while Shift is held.

### A as built (branch v039-room; image end 0xE6EA4 = 945,828 B, margin to 0xFC000: 86,364 B)
- **Engine** (`plinky_voice.h`): `Engine` now holds `kInstances = 3` `Inst` records (own p[] / ef[] and the control-rate state: smoothing, LFO phase, bend, mod wheel, level ramp) and a **pool of `kPool = 8` voices**, each tagged with its instance. All message calls take an instance (`noteOn(note, vel, inst = 0)` ...), so single-synth callers are unchanged. Per instance Voices limit 1..4. `pick()`: same note held -> that voice; idle slot while the instance is under its limit and the pool under the governor cap; else a victim - of the instance itself when it is at its limit, otherwise of any instance (quietest releasing voice, then the oldest note). A lowered Voices limit releases the extra voices (rank in pool order). **Old sounds are bit-exact**: golden FNV hashes of 3000 blocks (random notes, shapes, CCs, LFO, widths) from the v0.3.8 engine for Voices 1..4 are checked in `test_plinky3.inc`; the only difference is the dynamic case of changing the Voices limit while notes ring (the extra voices are chosen by rank, not by slot index).
- **Outputs**: the stream has 6 outputs: dry L / R, reverb send L / R, delay send L / R. Each instance's Reverb / Delay level (effective values, so CC 91 / 93 work per instance) is applied inside the engine (0.5 per side as before); the mixer inputs are at unity (`applyPlinkySends` only restores that). Send blocks are only allocated when some instance has a send level. Instances are summed with saturation.
- **Governor** (`plinky_governor.h`, own implementation of the control law of plan 018 section 1.1, nothing copied from OpenTracker): load of the previous whole audio block (`Profiler::lastAudioUs()` in permille of 2902 us); overrun >= 100 % -> cap = sounding - 1; risk (a block >= 98 %, or two >= 95 % within 1 s) -> one voice fewer, not below 4; average >= 88 % -> one fewer (down to 0), >= 80 % -> one fewer, not below 4; 250 ms hold-off after a cut; one voice back after 2 s with average < 65 % and no block >= 90 %. Voices over the cap fade out within one block (target amplitude 0 over the block, then freed): no click. Reset on project load. Host-tested (law, hold-off, restore, engine integration with a fake load, no click, bounded).
- **Glue** (`seqPlinky.cpp`): `Controller` (snapshots + morph) per instance in EXTERNAL_RAM (3 x 5.4 KB, raw storage + placement new in `seqPlinkyInit`), file buffer for three instances; MIDI routing by channel (instance k: channel parameter, default 16 / 15 / 14); `seqPlinkyInst / SetInst / CycleInst` = the instance the view shows (Get / Set / Default / marks / morph / voices follow it), `seqPlinkySetAll(param, delta)` for Shift + dial (`seqplinky::allValue`: clamped per instance, the morph time too), `seqPlinkyInstanceOf(instrument)`, `seqPlinkyInstrumentOf(inst)`.
- **plinky.bin**: instance 0 stays exactly the version 1 frame + `PLVM` trailer (an older mod reads PolySynth 1 from a new file); one `PLVI` v1 frame per other instance (and for instance 0 once it has parameters the old frames cannot hold, step B): instance, nParams, values, morph time, count, entries (pattern + values). A file without PLVI frames gives instances 2 / 3 their defaults; `fixChannels` keeps all channels distinct and 1..16 (a v0.3 file with another claimed channel keeps it for PolySynth 1; channel 0 -> 16). A default project writes the same bytes as before; a corrupt PLVI frame is skipped, a newer one leaves the file alone.
- **UI**: headline with tabs `SYNTH 1 | SYNTH 2 | SYNTH 3` (teal / yellow / violet = Note / Instrument / FX1 key colours; active tab filled, inactive dim outline); right of it the CPU, voice cap `V8`, or the morph; a bright `ALL` tag at the right while Shift is held. The Instrument Parameters key (Play mode: first press opens on the instance of the selected track, then cycles 1 -> 2 -> 3 -> 1; a screen button held + the key also cycles; Pattern key / leaving Play mode / another non-synth track closes; another synth track switches to its instance; instrument page: the Params key cycles the instance by choosing its instrument). **Shift + jog = ALL** replaces the old Shift = fine step (no fine step any more; the coarse step is 5 on 0..100). FIFO rule of v0.3.9 (a display stage is one burst into the 4 KB FT81x command FIFO, limit 3,840): the view stays ONE stage, its exact command FIFO bytes are measured by `test_plinkyseq.inc` over every cursor position and instance with the ALL tag, morph title, cap readout and four voices: worst 1,828 bytes (an earlier try with a conservative two-stage split was dropped: not needed, and a split risks a torn frame). The display budget test limit goes from 3,600 to 4,200 bytes (the tabs and ALL tag add 340 bytes; since v0.3.6 A1 the pattern control is hidden, so the share is the pitch view's 5,400).
- **Pitch view**: 8 pool voices as lines; colour = the voice's instance (the engine writes the instance into bits 1..2 of `TraceSample.on`), further voices of one instance a little lighter; the points per line shrink when more than 4 voices have data (budget unchanged: 8 full voices fit the two stages).
- **Instrument order** (`seqInstOrderLogic.h`, owner): PolySynth 1 / 2 / 3 first in the instrument popup (names `PolySynth n`) and in the Instrument + jog stepping (`Sequencer::changeInstrumentInSpecificOrder`), then the stock order; pure mapping between list position and instrument index, stored indices unchanged. The instrument editor's own list only holds sample instruments and is untouched.
- **Consequential test changes (equally strict)**: `test_trace` / `test_stages`: the ring has 8 voices (`kPool`), the chord cases use 4 voices and the instance colour `lineColor(0, v)`, the fake ring is zeroed; `test_plinkyseq.inc`: overlay budget 3,600 -> 4,200 (reason above). No expectation was loosened otherwise.
- **Not done / open**: fine step (see above); the numbers of the governor on the device (all thresholds are from plan 018 and untested); CPU readout still of the whole synth stream, not per instance.

### B as built (branch v039-room)
- **Parameters 21 -> 33** (appended; `kLegacyCount = 21` keeps the version 1 file and the PLVM trailer exactly as before): Sub -1, Sub -2, Type (LPG, SVF LP / BP / HP, Ladder), Filter env Amount (50 = off, +-5 octaves) / Atk / Dec / Sus / Rel, LFO Wave (7), Chorus Mix / Rate / Depth; LFO target 3 = Level. They are stored per instance in the PLVI frames (instance 0 gets one once it has a non-default new value or snapshot); an older build reads the legacy part. Masks of changed / marked parameters are 64 bit now (`ParamMask`), the morph switches Type and Wave at the start like the other stepped parameters.
- **Old sounds**: the defaults take the unchanged code path (the sub, filter and chorus code is behind per-block constants; the LPG filter envelope term is skipped at Amount 50); the golden hashes of the v0.3.8 engine still match, and a chorus memory with mix 0 renders the same bytes.
- **DSP** (`plinky_voice.h`, own implementations of the textbook topologies; plan 018 pointed at the OpenTracker (Apache-2.0) versions, they were not copied, so no new license text is needed): subs = two blep square waves (a saw pair half a cycle apart, the existing integer polyBLEP) one and two octaves below the pitch, level ramped over the block; SVF = zero delay feedback (topology preserving transform) low / band (peak gain 1) / high pass, coefficient `g = tan(pi fc / fs)` by a Pade approximation once per block per voice, ramped in steps of 32 samples, damping from Reso; ladder = four zero delay one poles with the feedback loop solved in closed form and a soft clip on the loop input (stable at any setting; Reso up to feedback 3.9); for SVF / ladder the amplitude envelope is a VCA after the filter, the cutoff is 1300 Hz * 2^((Cutoff-60)/10 + envelope octaves + LFO octaves) limited to 20 Hz .. 13 kHz; the filter envelope is a block rate ADSR per voice (it also moves the low pass gate cutoff); LFO shapes in `lfoShape()` (random values from a per instance LCG, a new value per cycle); chorus per instance: two int16 lines of 1024 samples (4 KB, raw EXTERNAL_RAM storage `s_chorus`, cleared by the engine when an instance had been idle), 10 ms centre, +-5 ms depth, rate 0.2 .. 6 Hz, triangle LFOs half a cycle apart, linear interpolation, wet share up to 50 %. The chorus loses 3 to 5 dB at full Mix on steady notes (comb filter); no make-up gain.
- **Cost** (host, -O1, 4 stereo voices, ns per voice-sample; the device numbers are estimates, not measured): plain saws 16.3, both subs 22.6, SVF 18.0, ladder 43.3, LPG + filter env 16.4, chorus (per instance) 18.9, everything 50.8. Estimate for the M4F from the instruction counts: subs +40 cycles per voice-sample, SVF +25 per channel, ladder +50 per channel (the most expensive piece: about one and a half times the old voice; Width 0 halves it), chorus about 100 cycles per sample per instance (SDRAM reads) = 2.5 % of the block per active chorus.
- **UI**: eight sections, five visible rows with a window that follows the cursor (thin scroll bar at the right edge, the selected row is always inside), the instrument page buttons name the visible rows; value texts for the new cells (`+2.5 oct`, filter and wave names, Level target).
- **Numbers**: image end 0xE80DC = 950,492 B (margin to 0xFC000: 81,700 B), FLASH 945,940 B, RAM 229,628 B (87.6 %), EXTERNAL_RAM 16,555,064 B (98.68 %; +31 KB: chorus lines, bigger stores and file buffer). Host: core/seqtest 90,330 + plinky 29,436 checks and the others, 0 failures; seqgen 103,346 checks, 0 failures.
- **Consequential test changes (equally strict)**: `P_COUNT == 21` became `kLegacyCount == 21 && P_COUNT == 33`; the section / navigation checks of `test_plinkyseq.inc` follow the eight sections (five visible rows); the plinky.bin fixture of `test_plinky3.inc` keeps instance 0 free of the new parameters (its own frame is tested in `test_plinky4.inc`).
- **Not done**: the drive shapes (soft / fold / asymmetric, plan 018 item 8; the Drive parameter is unchanged), the six double to float math call sites, a make-up gain for the chorus, CC numbers for the new parameters, hardware measurements of the CPU cost (please report V and the CPU readout with the ladder and the chorus on).

## B — engine extensions (same engine for all instances)
- **2 sub-oscillators**: square, −1 and −2 octaves, each with a level.
- **Filter designs**: selectable type — the current Plinky low-pass gate, plus SVF low-pass / band-pass / high-pass
  (12 dB) and a 24 dB ladder-style LP if affordable; cutoff/resonance/drive shared; **filter envelope** (ADSR + amount)
  separate from the amp envelope.
- **More LFO waveforms**: sine, triangle, saw up/down, square, sample & hold, smooth random; LFO targets as now + filter.
- **Chorus**: per instance, cheap (one modulated delay line per side, EXTERNAL_RAM raw storage), mix + rate/depth.
- Borrow concepts from tracker-ff engines where cheap (see plan 018), e.g. drive/fold shapes.
- All new parameters in the section UI (new sections Sub, Filter env, Chorus), morph-able, saved in plinky.bin
  (versioned; old files load, older mod versions read what they can).
- CPU: keep the per-voice cost close to today's; sub-oscillators and SVF ~cheap; ladder optional.
