## A — FX ranges and perform persistence
1. Reverb low cut (HP) can go higher: extend the range (now off/30 Hz–1.8 kHz) up to ~5 kHz, same semitone steps.
2. Delay feedback and reverb size: allow up to **95 % overall** "if possible" (now capped at feedback 88 / size 0.90
   because of crackle). Make 95 % clean: soft saturation inside the delay loop (exists) and inside the stock reverb
   tank / Plinky ring so near-unity settings don't crackle; host sims with loud sustained input must stay bounded and
   free of hard-clip steps. Same cap on the fader page and the Master page.
3. **Dialled-in perform effects stay engaged when switching to another menu** (any module, not only Pattern/Song).
   They end only by DISENGAGE / unlatch / Stop panic.
4. **The fader page's track selection always stays the last user setting.** Stop/Play (panic), disengage, module
   switches and re-entry must not clear it. Only the user changes it.

## B — Plinky as a sequencer type in Play mode, with a parameter overlay
- In Play mode (bottom-right Perform = Pattern key, tapped), a new sequencer type **Plinky** for a track: the track
  plays the Plinky voice from the pads (provisional layout: Plinky-style "strings" — the 12x4 pads as scale notes,
  columns = strings, rows = notes, root/scale from the track; record/takeover like the other types). Selecting the type
  claims the voice for that track automatically (no MIDI-channel setup needed); the stock instrument-page way stays.
- **Instrument Parameters key** (while that track is selected in Play mode; owner: "with the first button and
  instrument parameters button") opens a **UI overlay** with all Plinky voice parameters in a clear layout grouped by
  section — Oscillator (waveform/shape, detune, interval, noise), Low-pass gate / filter (cutoff, resonance, drive),
  Envelope (attack, decay, sustain, release), LFO (rate, depth, target), Voice (voices, glide, width, level, reverb/delay
  send). **Arrow keys move between parameters, the jog wheel changes the value**; the same key (or Instrument
  Parameters again) closes it. Values and section names readable at a glance; current value as bar + number.

## B as built (branch v03-plinkyseq)
Naming (owner): "PolySynth" in everything the user reads (type list, strip `POLY`, legend, overlay and instrument-page titles); "Plinky" stays in code identifiers and in the credit (README / NOTICE.md / source headers).

**Type.** `TYPE_PLINKY = 11` (appended after the 8 HYPER_RASP types, `TYPE_COUNT = 12`; `isHrType` ends below it). Old `seqtracks.bin` load unchanged. The setup (root, scale, octave, string spacing; 4 bytes) rides in the existing optional per-track trailer (the one the HR types use), written only when a track is PolySynth; the file version is NOT changed (older firmware turns that track Off and skips the trailer; a file without a PolySynth track is byte-identical to before). The setup is in the change-detection hash only while a track is PolySynth.
**Pads** (`core/source/seqPlinkySeqLogic.h`): column c, row r (row 0 on top): scale degree `c * interval + (3 - r)`, interval default 3 (a 4th in a 7 note scale), default C minor, octave 2 (bottom left = MIDI 36); 8 scales. The bottom right pad toggles the setup view (row 0 root, row 1 scale + octave, row 2 spacing). Neighbouring strings overlap: a note two held pads share starts once and ends with the last pad. Pad pressure (`velo`) is carried through the command queue (new field `b` of the command); 0 = fixed 100.
**Engine** (`seqTracksCore`): `padPlinky` emits the note events through the same sink as the generators, so takeover, mute, recording (`recFeedOn`, chords by pulse) and `releaseAll` work unchanged. `takeover = held pad or sounding note` only (a PolySynth track is never taken over by the transport). One owner: `applyType` refuses a second PolySynth track; the UI checks `plinkyOwner()` (including the pending type) first and shows `voice on T3` in the asking cell. Setup is engine-wide (one voice).
**Claiming / routing** (`seqPlinky.cpp`, `seqTracks.cpp`): the track plays through the MIDI instrument whose channel is the voice's `P_CHANNEL` (the existing MIDI-channel takeover, no new path), so a recording writes MIDI-instrument notes on that channel and the pattern plays the voice without the sequencer. `seqPlinkyClaim()` (main loop, called when the type is chosen and again when a PolySynth track appears, e.g. a project load) gives the voice a channel only when it has none: the last used MIDI instrument, else MIDI 16. The host reports such a track as not a sample track (polyphony, MIDI chords in the recording).
**Overlay** (`seqPlinkyUiLogic.h`, drawn by `cSeqPlayLegend`): 5 section rows x up to 6 cells (20 parameters; the channel is in the title), cursor Left/Right = parameter, Up/Down = section (no wrap, column kept), jog (3 detents at most per event; 5 per detent on 0..100 values, 1 on short ranges or with Shift), Delete (Default) resets, the Instrument key toggles (also with screen button 1 held), the overlay closes with Play mode, a popup, another track or type. It owns the wheel while open (the type list is off). Display list measured in the host test: worst case 3564 B (empty bars 3076 B) of the 8172 B frame, everything inside x 0..800, y 30..424 (the strip stays visible). It is redrawn at most every 100 ms for the CPU readout.
**Review fixes of the voice** (same branch, from the coordinator's review): CC changes the effective values `ef[]` the DSP reads and never the saved `p[]` (a UI edit takes the effective value back); the reverb / delay mixer gains follow the effective sends (`seqPlinkyUpdate` compares with the last applied values); a release that finds the event queue full is remembered per note (32 bit atomics) and applied by the next block, likewise all-notes-off; `noteOn` returns false when dropped and `seqPlinkyNote` passes that on; a note-off that arrives before the voice's first block is applied after it (the note sounds one block instead of never); velocity 0 releases; the Config "middle C" shift is applied like `sendMidiNoteOn`; claiming a channel sends all-notes-off (CC 123) to the MIDI outputs of that channel first; the voice is declared before the mixers (updated first); a newer `plinky.bin` is announced in the overlay and on the instrument page. (h) The filter idle shortcut (`filter_variable.cpp`) already requires `overdriveGain == 0`; no change was needed.
