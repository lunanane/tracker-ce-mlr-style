# Plan 010 — owner feedback on v0.2.6 hardware test (2026-11-05)

Owner: "v0.2.6 is great! Plinky reverb works absolutely nicely."

## A — FX ranges and perform persistence
1. Reverb low cut (HP) can go higher: extend the range (now off/30 Hz–1.8 kHz) up to ~5 kHz, same semitone steps.
2. Delay feedback and reverb size: allow up to **95 % overall** "if possible" (now capped at feedback 88 / size 0.90
   because of crackle). Make 95 % clean: soft saturation inside the delay loop (exists) and inside the stock reverb
   tank / Plinky ring so near-unity settings don't crackle; host sims with loud sustained input must stay bounded and
   free of hard-clip steps. Same cap on the fader page and the Master page.
3. **Dialled-in perform effects stay engaged when switching to another menu** (any module, not only Pattern/Song).
   They end only by DISENGAGE / unlatch / Stop panic.
4. **The fader page's track selection always stays the last user setting.** Stop/Play (panic), disengage, module
   switches and re-entry must not clear it. Only the user changes it.

## B — Plinky as a sequencer type in Play mode, with a parameter overlay
- In Play mode (bottom-right Perform = Pattern key, tapped), a new sequencer type **Plinky** for a track: the track
  plays the Plinky voice from the pads (provisional layout: Plinky-style "strings" — the 12x4 pads as scale notes,
  columns = strings, rows = notes, root/scale from the track; record/takeover like the other types). Selecting the type
  claims the voice for that track automatically (no MIDI-channel setup needed); the stock instrument-page way stays.
- **Instrument Parameters key** (while that track is selected in Play mode; owner: "with the first button and
  instrument parameters button") opens a **UI overlay** with all Plinky voice parameters in a clear layout grouped by
  section — Oscillator (waveform/shape, detune, interval, noise), Low-pass gate / filter (cutoff, resonance, drive),
  Envelope (attack, decay, sustain, release), LFO (rate, depth, target), Voice (voices, glide, width, level, reverb/delay
  send). **Arrow keys move between parameters, the jog wheel changes the value**; the same key (or Instrument
  Parameters again) closes it. Values and section names readable at a glance; current value as bar + number.

## A as built (branch v03-fx)
1. **Low cut to ~5 kHz**: `kHpMax` 72 -> 90 (30 Hz .. 5126 Hz, same semitone steps; index 72 is still 1.8 kHz). The sidecar range check
   is `hp <= kHpMax`, so every old value stays valid. The fader/Master display uses the same mapping (no UI change needed).
2. **95 %**: `kReverbSizeCap` 0.95, `kDelayFeedbackCap` 95 (`seqFxCaps.h`; the fader page top step and the engine setters follow). What
   crackled was the hard clip inside the loops, so: (a) delay unchanged (it already soft-limits; the host model is clean at 95);
   (b) stock reverb: `softSat` (identity up to 5/8 of full scale, then `t + (1-t) u/(1+u)`, smooth, bounded below 1) on the accumulator
   before every write of the tank (dap1a, dap1b, del1, dap2a, dap2b, del2) and on the wet return (`softSat16(wet*32768)` before the
   mix, which also removes the wrap of the float -> int16 conversion above full scale; the mix of input and a value inside the range cannot
   leave the range); (c) Plinky ring: `satw` (= `softLimit` + `ssat16`) on every stage write and on the output. Everything is the identity
   below the knee, so **the stock reverb stays bit-identical to the frozen reference** in every `test_cpu` case, loud ones included, and
   a new quiet/moderate case at 95 % was added. Consequences stated, not weakened: `test_fx` size/feedback cap checks now say 95;
   the delay-model smoothness bound is 0.3 of the peak up to the old cap 88 and 0.4 above (measured 0.356 at 95 % / 32000: a compressed
   waveform through its zero crossing), with a **new strict check** that no step above 1/8 of the peak ever happens within 28000 of the rails;
   the ring all-pass "equals the original" test models the soft write above 20480 (identical below). New host sims (`test_fx.cpp`): the real
   `Reverb` at 90/95 % x damp 0.2/0.5 with sines 8000/20000/32000 (80 Hz), 32000 at 1 kHz and full-scale noise (8 s, mono): peak < 31000,
   energy settled, near-rail step < 3500 (sines), no wrap; the ring at 95 % with shimmer 32/127: zero rail hits, near-rail step < 6000.
   The ring's size mapping saturates (fade 250/256 from size 0.9 on), so 0.95 does not change the ring's loop gain; the soft write is
   what keeps it clean.
3. **Shimmer**: `RingReverb::setShimmer(0..127)`, default 32 (= the former fixed value), smoothed in the ring at 2 units per block
   (full sweep ~0.2 s). Master > Reverb item 7 "Shimmer" (percent 0..100 = raw*100/127; 25 % = 32 exactly; jog 1 %, Default key = 25), shown
   only with the Plinky type (UI name now "ShimmerReverb", owner naming); with Stock item 7 stays the CPU readout, which moves to the
   title bar's right label while ShimmerReverb is active. `seqfx.bin` version 2: payload byte 3 = shimmer, bytes 4-5 = track selection mask;
   a version 1 file loads with default shimmer and no stored selection (the v1 zeros are not read as values). Not added to the REV fader page.
4. **Perform FX on every module switch**: `leaveFor` returns KEEP_RUNNING for every destination when something is dialled in (Performance
   stays HAND_OVER: it is not a switch away). The `interface.cpp` ending (`seqFaderEndKept`, `endKeptStockRule`) is removed; the stock
   Master / Instrument-parameters `functSwitchModule` no longer turn performance mode off while `seqFaderKept()`. Gates kept: owner mask,
   pattern reload only with per-track patterns, no SD write while playing. Still ends the FX (by design): DISENGAGE/unlatch, Stop panic,
   project load (they belong to the old project), the stock Performance page starting fresh (it resets its own rows; Shift + Performance from
   the fader page hands them over instead), and the stock "Continue song" turn-off (not a module switch).
5. **Track selection**: the source of truth is `seqFxTrackSel()` (mask, in `seqfx.bin` v2). Only `trackButton` and a hand-over from the stock page
   write it; the engine's track states (zeroed by every `turnOff`, by the stock page and by project load) are restored from it on page entry,
   at the end of `stop()`, after the panic and after `projectLoaded()`. Persistence: the first `seqfx.bin` read after power-on supplies it, later
   project loads keep the current selection (a performance preference, not a project property); saving writes the current mask into the
   project's file (deferred while playing as before).
6. **Extras (coordinator)**: reverb and limiter treat a missing input block as zeros (allocate + clear); comment at `connectInputToMixer`;
   `Profiler::sampleHeap()` (main loop, every 16th pass) keeps the minimum free heap, shown as "free heap: A, min B B" on the Config page, with
   a device-test row. Heap/stack: after plan 009 P the region between `_ebss` and `_estack` is 0xAEBC = 44 732 B for heap + stack; that is tight
   by design but cannot be judged without a device reading, so `sramReverbBuff2` stays in SRAM; if the new minimum is < ~6 KB (or stack
   free < ~4 KB) move it back to SDRAM (a 22 KB `.reverb_memory` array would have to be re-added). `externalRamReverbBuff` (32 KB SDRAM) is
   now only built for the IMX platforms (Tracker.cpp, mtTest.cpp, effect_polyverb.cpp guarded).
Not device-tested: the UI (Shimmer row layout, title-bar CPU label), the cap sound on hardware, the heap numbers.
