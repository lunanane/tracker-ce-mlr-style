## B1 — MLR → launcher screen stuck (bug, found on v0.2.2)
Screen button 8 in the CUT/MLR layer switches back to CLIPS, but the MLR lanes stay on screen and the launcher grid
is not drawn ("stuck in MLR"). Fix the layer handover (CutSessionLayer leave / laneViewDestroy vs ClipsLayer enter /
grid show + forced recomposite), both directions, repeatedly; host test where possible.

## B2 — launch quantise ignores the setting in long sequences (bug, found on v0.2.2)
Owner: "no matter what's set, in long sequences it always counts down about 128 bars before launching the next one."
Quantise must follow the chosen value (NOW / beat / bar / … as cycled by screen button 2) relative to the global
position, independent of pattern / clip length. Check Q_BAR / quantHit / countdown and the launcher's step counting
for long patterns (128 steps), scenes (stock pattern switch waits for the pattern end — decide and document how scene
quantise relates to the pattern end), Play 1x follow actions.

## F1 — ping-pong delay filter becomes a bandpass
Owner: "change the fx send ping pong filter to being a bandpass filter." Decision: the existing delay filter control
(PING fader page filter row, stock Master delay filter param `delayFilterFrequency`) becomes the bandpass **center**;
width fixed at a musical Q (~1 octave). Same fader count. Audio-path change on MK66 — keep CPU cost minimal
(one biquad / state-variable filter per channel), no clicks when the center moves (smooth coefficients).

## F2 — reverb highpass
Owner: reverb gets a highpass (low cut) "which fits the application better"; damp stays. Decision: the REV fader page's
**predelay** row becomes **HP (low cut)**; predelay keeps its project value and stays reachable where it is in stock
(Master page). HP applies to the reverb input (or return) so the reverb stays clear of kick/bass. Saved as a project value
alongside the stock reverb params (check strMtProject layout / version compatibility — prefer a sidecar or spare field
over changing the stock project struct).

## Owner change (2026-11-04): Song key toggles Song page <-> launcher (supersedes the v0.2.2 double tap)
"I just want the Song button to toggle between the stock Song mode and the launcher - no complicated tap-tap."
- Any other page: Song = stock Song page. Song page: a plain press + release of Song (nothing else held or used, no hold event) opens the
  launcher, whatever the Song page focus (the old early return at place 2 does not block it). Launcher (CLIPS or CUT): Song = Song page.
- The stock hold (momentary peek) is unchanged; a hold on the Song page itself does not toggle. It is decided by the keys driver's hold
  event (seqlogic::SongToggle), not by a time window. A Song press that began on another page never opens the launcher on its release.
- The DoubleTap logic (seqlogic::DoubleTap, seqSongDouble / seqSongDoubleNow, seqClipsSongTap hook) and its test are removed with the feature;
  test_song_toggle covers the new decision with the same strictness.

## Done notes (v0.2.4 work, 2026-11-04)
- B1: the CLIPS <-> CUT handover no longer destroys display controls. A destroyed control with a queued refresh stalls the display refresh
  queue for good (display.cpp step1 returned on the empty slot), so the launcher grid was never drawn again. The lane controls are created once
  per module start and only shown / hidden; the grid is forced to redraw on entry; the display queue now drops an entry of a gone control.
- B2: scenes follow the launch quantise (bar / now): the scene's pattern is read at launch (asynchronous), the sequencer interrupt swaps it in at
  the quantise boundary with every track at (global position mod its loop length), the last two steps belong to the stock pattern-end switch
  (never dropped), edits during the countdown restart the read (which saves first), Rec makes it a pattern-end scene. Q pattern and the Song
  page queue stay the stock switch. Play 1x follow actions wait for the clip end by design.
- B3: the Performance key routing is one tested decision (seqlogic::performKeyRoute): plain from any other page = fader page, Shift = stock
  Performance page; on the fader page plain stays and Shift goes to the stock page; on the stock page plain flips the tracks and Shift goes to
  the fader page. The code path was checked for every module; no defect was found in the source, hardware check pending with v0.2.3.
