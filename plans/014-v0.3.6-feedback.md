v0.3.5 boots and works. Big feedback round:

## A — PolySynth pages
1. **Overlay gets pushed out**: in Play mode with the PolySynth overlay open, whenever the pattern view below updates,
   the overlay disappears and the screen shows the stock pattern page *without its buttons/header*. Likely the frame
   display list overflows (pattern editor + strip + overlay > 8172 B → display.cpp step3 drops the lowest-index
   controls: title bar, labels) or a stock refresh repaints over it. Fix robustly: while the overlay (or pitch view) is
   open, hide/suspend the pattern editor's heavy controls (the overlay covers them anyway) so the frame fits, and make
   sure stock refreshes can't hide our control; restore on close. Host-check the frame sum where possible.
2. **Instrument page = the new layout**: the PolySynth Instrument Parameters page (the "quick access" page outside Play
   mode) must use the new section layout (Oscillator / Filter / Envelope / LFO / Voice, arrows + jog, Shift fine,
   Delete default, Morph, voices footer) instead of the old 4 pages. Pitch view reachable there with the same key (FX2)
   and labelled.
3. **Pitch view shows basically nothing** — no chord stabs visualised. Find why (engine ring not written? head/stride
   wrong? follower not fed / only fed while the overlay is open? auto range? drawn under the overlay? off-screen?) with a
   host test that drives the REAL engine (note-ons from a chord, glide, LFO) through the ring into the follower and the
   drawing, and asserts visible points for every sounding voice. Chords (4 voices) must show 4 lines.

## B — Master amplitude view, redesigned (reference: nathanmatsuda's PSP/phone "spectrum" visualiser)
- **Per-track amplitude**, each track its own colour (tracker key colours + variants for 8/16 tracks; the master as a
  thin neutral line optional).
- **Exponential time axis**: new data rushes in at the right edge and slows down / compresses exponentially towards
  the left axis, like the reference (screenshot 1 is the same idea rotated 90°): recent history at full resolution,
  older history progressively merged.
- Data structure: a fixed backlog of buckets with exponentially growing spans (1, 1, 2, 2, 4, 4, 8, …) — each new block
  peak enters bucket 0, buckets cascade-merge by averaging (or max) when full, so memory and drawing cost are constant
  (≈ 32–48 buckets × tracks). x of a bucket = f(log age).
- Look: like the reference — dark background, fine dotted grid, thin contour-like lines per track, labels (dB scale,
  time marks "15s / 5s / 1s" on the compressed axis), header with BPM / pattern / position if cheap.
- Data source: the existing per-track RMS/peak meters (14 analyzers incl. per track) or per-track block peaks at the
  track mixer inputs — cheap, no per-sample log (dB by table), only while the view is open.

### B as built (v0.3.6)
Files: `core/source/seqAmpViewLogic.h` (rewritten: dB table, `Cascade`, `xOfAge`, `Follower`, `draw`), `core/source/seqPalette.h`
(`trackColor`), `core/interface/masterParams/ampView.{h,cpp}` (data gathering), `core/seqtest/test_amp.cpp` (`make test`, target
`seq_amp_tests`). `traceControl.{h,cpp}` is unchanged (the draw template keeps its context interface and `draw(c, follower, title, hint)`
signature), so it does not collide with the pitch-trace fix. Button placement unchanged (Global Mixer 3/3, screen button 8).
- **Lanes**: the 8 sample tracks (`instrumentPlayer[t].getRMSValue()`, the lazy RMS meter that is armed by the first read; on the Global
  Mixer 3/3 page nothing else reads the track meters) and the master (limiter peak tap, max of L / R). Tracks 9-16 are MIDI tracks and
  have no audio; the PolySynth has no own meter (it is in the master line). One value per 40 ms (25/s), only while the view is open.
- **Cascade** (per lane, constant): exponential histogram. Bucket {avg u16, max u16, span u32}; the newest value enters bucket 0 (span 1);
  when three buckets of one span exist, the two oldest merge (span-weighted average, maximum kept) into one of the next span; a bucket of the
  top span (2048 blocks = 82 s) absorbs whatever is older. At most 2 buckets per span, <= 25 buckets (212 B per lane, 9 lanes = 1.9 KB), steady
  state about 1,1,2,2,4,4,... plus the transient carries of a binary counter. Work per block: one push, O(25).
- **Time axis**: x = X1 - W * ln(1 + age / 0.8 s) / ln(1 + 120 s / 0.8 s); age of a bucket = its middle; newest at the right edge, 120 s at
  the left axis (older buckets are cut, the first one past it is the last point). Marks (vertical grid lines): 1 s, 5 s, 15 s, 60 s, 2 min. The
  last second takes 16 % of the width, 60 s - 120 s about 14 %. `logf` is called once per bucket and mark per refresh (geometry is shared
  by all lanes); the dB conversion is the 65 entry table (0.04 dB), no log per sample.
- **Look**: tracks overlaid in one dB plot (0 to -60 dB, an offset lane per track would bend the dB scale), average line in the track colour
  (`seqpal::trackColor`: 1-4 the key colours Note / Instrument / FX1 / FX2, 5-8 lightened 43 % towards white, 9-16 dimmed) with the dim line of the
  bucket maxima behind it; master in light grey, thinner; silent lanes are not drawn; faint solid grid (dotted lines would cost hundreds of
  segments); header boxes pattern + step, BPM, title; hint "Amp view: close". Not done: LUFS (needs K-weighting), the dotted grid, the L / R split.
- **Numbers (host)**: display list 8 loud tracks + master 2232 B (limit 4096), silence about 0.8 KB; refresh <= 25 fps and the audio tap only
  while open. Tests: dB table, cascade (spans, constant size over 200000 pushes, merge average and maximum, recent data at full resolution,
  old data wide), age -> x (monotone, compressing, marks in order), per-track lane mapping and colours, layout bounds, budget.
- **Test consequence**: the old `test_amp_view` (L above / R below, ring decimation) of `test_trace.cpp` described the replaced design; its
  dB table / heightOf / follower-timing / budget / bounds checks are carried over in `test_amp.cpp` (same or tighter limits). Nothing else changed.
- **Not verified on a device**: the on-screen look, RMS meter arming on a real device (first block shows silence), refresh cost.
