# Plan 014 — owner feedback on v0.3.5 (2026-11-05, hardware)

v0.3.5 boots and works. Big feedback round:

## A — PolySynth pages
1. **Overlay gets pushed out**: in Play mode with the PolySynth overlay open, whenever the pattern view below updates,
   the overlay disappears and the screen shows the stock pattern page *without its buttons/header*. Likely the frame
   display list overflows (pattern editor + strip + overlay > 8172 B → display.cpp step3 drops the lowest-index
   controls: title bar, labels) or a stock refresh repaints over it. Fix robustly: while the overlay (or pitch view) is
   open, hide/suspend the pattern editor's heavy controls (the overlay covers them anyway) so the frame fits, and make
   sure stock refreshes can't hide our control; restore on close. Host-check the frame sum where possible.
2. **Instrument page = the new layout**: the PolySynth Instrument Parameters page (the "quick access" page outside Play
   mode) must use the new section layout (Oscillator / Filter / Envelope / LFO / Voice, arrows + jog, Shift fine,
   Delete default, Morph, voices footer) instead of the old 4 pages. Pitch view reachable there with the same key (FX2)
   and labelled.
3. **Pitch view shows basically nothing** — no chord stabs visualised. Find why (engine ring not written? head/stride
   wrong? follower not fed / only fed while the overlay is open? auto range? drawn under the overlay? off-screen?) with a
   host test that drives the REAL engine (note-ons from a chord, glide, LFO) through the ring into the follower and the
   drawing, and asserts visible points for every sounding voice. Chords (4 voices) must show 4 lines.

## B — Master amplitude view, redesigned (reference: nathanmatsuda's PSP/phone "spectrum" visualiser)
- **Per-track amplitude**, each track its own colour (tracker key colours + variants for 8/16 tracks; the master as a
  thin neutral line optional).
- **Exponential time axis**: new data rushes in at the right edge and slows down / compresses exponentially towards
  the left axis, like the reference (screenshot 1 is the same idea rotated 90°): recent history at full resolution,
  older history progressively merged.
- Data structure: a fixed backlog of buckets with exponentially growing spans (1, 1, 2, 2, 4, 4, 8, …) — each new block
  peak enters bucket 0, buckets cascade-merge by averaging (or max) when full, so memory and drawing cost are constant
  (≈ 32–48 buckets × tracks). x of a bucket = f(log age).
- Look: like the reference — dark background, fine dotted grid, thin contour-like lines per track, labels (dB scale,
  time marks "15s / 5s / 1s" on the compressed axis), header with BPM / pattern / position if cheap.
- Data source: the existing per-track RMS/peak meters (14 analyzers incl. per track) or per-track block peaks at the
  track mixer inputs — cheap, no per-sample log (dB by table), only while the view is open.

## A as built (v0.3.6, branch v036-poly from seq-tracks a5797a7 = v0.3.5; Original Tracker only)

**A1 root cause and fix (view switch, owner decision).** `display.cpp` step3 appends the shown controls from the highest table index down while the running sum stays under 8172 bytes and then **drops every remaining control, i.e. the lowest indices** (title bar, labels, the Play overlay, the trace view). The stock pattern control alone is about 4 - 7 KB (rows x tracks x characters as bitmap vertices), the PolySynth overlay up to 3.6 KB, the pitch view up to 2.8 KB: together over the budget, so the overlay (lowest index of the three) and the title bar fell out whenever the pattern refreshed. Fix in `seqPlayOverlay.cpp::syncPattern()`: while the PolySynth view is open (`plinkyOpen_`, parameter page or pitch view) the **pattern control is hidden** (`setControlHide`), so the frame is page + title + strip only; the pitch view hides the page control as well (`pitchOnly`: both together would not fit). `syncPattern()` runs every pass (a stock `setControlShow` is undone at once) and restores exactly on close / leaving Play mode (`setControlShow`, `refreshPattern`, only when no stock popup owns the screen). A generic guard uses the new `cDisplay::shownRamBytes()` (sum of `ramSize` of the shown, refreshed controls): any other overlay (legend, type list) that would push the sum over 8172 - 64 also suspends the pattern control until it closes. Host model: `test_frame_budget_model` (pattern worst estimated from tracker.cpp, overlay 3600, pitch 2800 / 4096 limit, strip, title).

**A2 instrument page.** The PolySynth Instrument Parameters page is the Play-mode view: a `cSeqPlayLegend` control in mode PLINKY drawn by the same `seqplinky::draw`, filled by the shared `seqPlinkyFillModel` (track 0 = no track number; its own title / hint line). Keys: Left / Right parameter, Up / Down section, jog (Shift fine), Delete default, FX2 pitch view; screen buttons 1-5 jump to a section, button 7 `Pitch view / FX2` (any screen button closes the pitch view). Stock page controls are hidden (bars, lists, frame). The title bar shows `PolySynth Instrument  CPU n% pk n%` (or the morph). Non-PolySynth instruments are untouched.

**A3 why the pitch view showed (almost) nothing.** (1) The same frame overflow as A1: pattern + page + the pitch view 2.6 KB: the trace control (lowest index) was dropped. (2) A real engine defect found by the new host test: the ring was written every 12th *rendered* block and only the state at that instant counted, so a stab (attack + release in less than ~35 ms of rendering) or a note that ended before the next sample never produced an `on` sample, and the engine going idle wrote no closing sample. Sustained chords were fine on the old code (the test passes there). Fix: `latchTrace` per voice (on / pitch / envelope of the last rendered block), `writeTrace` writes the latch and clears it, a flush plus a closing (all off) sample when the engine goes idle; follower `push` keeps a note on screen for at least `kMinRun` = 5 samples (~175 ms, the last point with the envelope falling), `decimate` marks a bucket on when any sample in it is on. Test: `test_real_engine_chord_visible` (sustained 4-note chord: 4 lines at 4 heights; staccato chord stab twice: 4 voices each; first note after the view opened; glide slope; LFO wiggle; bounds); on the v0.3.5 headers it fails (12 checks).

**A4 pad LEDs (owner hardware).** `seqplay::LedGuard`: all 48 LEDs are rewritten after a popup / the type list closed, on a track or type change, after a stock edit key, and every 500 ms; nothing is written while a popup owns the pads (`padsBacklight.clearGlobalPads` when it returns). `ledPass` is the shared diff / full write. `test_led_guard`.

**A5 legend tap.** The wheel only cancels the tap toggle when it really opened the type list; an Off track answers a tap with `pick type first` (no empty legend); the strip hint `tap: help` stays on the selected cell, the PolySynth hint flashes in for 0.7 s every 4 s (was half of the time). `test_tap_legend_robust`. The real event flow (press / release owned by `ScreenHold`, `LegendGate` toggles on the release of a tap on the selected track) was re-read; the likely reasons for lost taps on the device are the frame overflow (the legend control is a low-index control and was dropped, A1) and the wheel nudge; not reproduced on a device.

**Test changes (consequences, equally strict).** None of the existing expectations was changed. New: `test_real_engine_chord_visible`, `test_frame_budget_model` (test_trace.cpp), `test_led_guard`, `test_tap_legend_robust` (test_play.cpp). `test_pitch_layout_and_size` case 2 (on/off runs of two) now sees the minimum visible length (the follower stretches short runs); its size and bounds checks still pass unchanged.
