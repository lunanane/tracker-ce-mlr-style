# Plan 031 - v0.4.8 fixes (as built, views branch)

## Amp view / Pitch view do not show (owner, device v0.4.6)

Lead: display.cpp cDisplay::step3 appends the visible controls from the highest index down and stops at the first one that does not fit
the 8172 B frame. The trace control has the lowest index, so it is dropped silently while the page under it is hidden.

As built:
- display: per frame the appended bytes, the number of visible controls dropped by the budget and the running maximum of both
  (frameBytesLast/Max, skippedLast/Max); `ramUsedByOthers(idx)` = ramSize of the other visible controls with the refresh flag, exactly the set
  step3 appends (same as shownRamBytesExcept, which the amp view already used).
- `tracestage::frameRoom(others, design)` = min(design, 8172 - others - 256), never below 0 (seqTraceStages.h).
- Amp view: `ampview::traceBudget` = frameBudget, but below the 2600 B floor it follows the real frame (reduced frame instead of nothing).
- Pitch view: the follower has a `budget` (default kDisplayBudget, no change in the usual case); a smaller budget thins the curve points in
  proportion (floor 4 / 3 points).
- hideControlUnderMenu hides name labels and bars 0..7 (the Amp view button is label[7], a different control).
- step3: `break` NOT changed to `continue`: lower indices are drawn on top of the dropped control, so drawing them without it would show
  overlays on a missing background; the dropped count is reported instead.
- Config > CPU monitor: line "Display: frame <B> B (max <B>)  skipped <n> (max <n>)". (No stack headroom line exists in this branch.)
- Tests: seqtest test_amp / test_trace / test_cpu_monitor (budget for others 2320 / 4000 / 6000 / 7900, text fits buffer and stage);
  devstub/display.h got `ramUsedByOthers`. No existing expectation changed.
