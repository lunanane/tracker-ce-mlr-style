# Plan 012 — PolySynth parameter snapshots per pattern / clip with a timed morph (owner 2026-11-05)

Owner: "It sounds absolutely fantastic, the PolySynth! I need it to save parameters per clip or pattern, and have them
morph with a fixed transition time when changing the pattern or clip — like a 6 second linear morph between what's
dialled in per pattern (or clip if triggered individually)."

## Behaviour (lead defaults, owner may adjust)
- **A snapshot per pattern**: the PolySynth parameters belong to the pattern they were dialled in on. Editing a
  parameter (instrument page or Play-mode overlay) writes it into the snapshot of the pattern currently playing
  (or shown, when stopped). A pattern without its own snapshot inherits — switching to it changes nothing.
- **Morph on change**: when the playing pattern changes (stock pattern switch, song advance, launcher scene, queued
  Song-page slot, follow action) every continuous parameter moves **linearly** from its current value to the new
  pattern's snapshot over the **morph time** (default **6 s**). Stepped parameters (voices, LFO target, waveform if
  stepped) switch at the start of the morph.
- **Clips**: a clip launched individually on a track whose instrument is PolySynth morphs to the snapshot of the
  clip's source pattern (the engine is shared: the last launch wins).
- **Morph time**: one setting per project, 0–30 s (0 = jump), in the PolySynth Voice section; saved with the project.
- During a morph, turning a parameter by hand takes that parameter out of the morph (hand wins) and writes the snapshot.
- Storage: snapshots in the PolySynth sidecar (plinky.bin, new version, older files load as "one snapshot for all");
  in RAM in EXTERNAL_RAM (255 patterns × params), not internal SRAM (83 % used). No SD writes while playing.
- Display: the overlay/instrument title shows "Morph 3.2 s → P12" while a morph runs; a small mark on parameters
  that differ from the inherited value.

## As built (v0.3.3, branch v033 from seq-tracks 9101370 = v0.3.2; Original Tracker only, `make original`)

**Morph (core/source/seqPlinkyMorphLogic.h, host-tested; glue in seqPlinky.cpp).**
- `Store`: one snapshot per pattern 1..255 (all 21 values; the channel is kept but never applied), a bitmap says which patterns have one, 5.4 KB in `__NOINIT(EXTERNAL_RAM)` together with the 5.4 KB file buffer (internal SRAM untouched). `base` = the values of the last loaded file (old files: the one block).
- `Morph`: integer-rounded linear interpolation, `start` + (`target` - `start`) * elapsed / duration, evaluated by the main loop pass (`seqPlinkyUpdate`, about every 5 ms) and written with `Engine::setParam`, i.e. into the existing block-rate smoothing (about 12 ms one pole + per-block ramps): no clicks, no audio-side change, a loop over 20 bytes per pass while a morph runs. Stepped parameters (Voices, Interval, LFO target) switch at the start; Shape stays continuous. A new begin() takes the engine's current values as the start (interrupt mid-morph = no jump); `hold(param)` takes a parameter out of the running morph (hand edit), released at the next begin.
- Triggers: one watcher on `mtProject.values.actualPattern` in `seqPlinkyUpdate` covers every path that really changes the playing pattern (stock switch, song advance with plan 006 loop / play-next, launcher scenes with quantise, Song-page queue, Play 1x follow actions all end in `switchRamPatternsNow`). Playing: morph over the project time; stopped: the snapshot applies at once. A pattern without a snapshot inherits (nothing changes, a running morph goes on). Clips: `launchClips` (every launch incl. the follow action) calls `seqPlinkyClipLaunched(track, pattern)` after success; if the track's instrument is the PolySynth the morph targets the clip's source pattern (`clipTarget`); it starts at the launch, not at the quantise point (6 s dwarfs the quantise); last launch wins.
- Edits: `seqPlinkySet` (instrument page and overlay both) writes the snapshot of `actualPattern` (the playing pattern, or the shown one when stopped); the first edit of a pattern copies all current values (during a morph: the morph targets) so the sound of the moment becomes the pattern's own. CC automation is not written. The morph time is a project value (`halfSec`, 0..60), "parameter 21" for the UI.
- UI: overlay Voice row has 7 cells (Morph last); the row geometry changed (cell step 96, width 92, bar 80). Instrument page: page 3 place 7 (page 1, the Voice page, has no free place). Title `T2  Morph 3.2s > P12` (overlay) / `PolySynth 3/3  Morph 3.2s > P12  CPU n%` (page). Mark: `*` after the name of a parameter whose snapshot value differs from the inherited one (nearest lower pattern with a snapshot, else the file's base); on the instrument page the label gets the `*` too.
- Storage: `plinky.bin` = the unchanged version-1 frame (written with the values dialled in, an older mod reads exactly that) followed by an optional trailer frame `PLVM` v1: morph time, count, entries (pattern + 20 values). Only patterns with a snapshot are stored; nothing to say (no snapshot, 6 s) = the file is byte-identical to the old one. An old file loads as the base with no entries; a bad trailer CRC is ignored, a newer trailer version leaves the file alone. Writes stay deferred until the transport stops (existing dirty gate; the dirty hash now covers values, time and snapshots).
- Numbers: image end 0xDA8B0 (< 0xF0000); EXTERNAL_RAM +10.8 KB.

**Play-mode keys (owner, in order of arrival).** Instrument Parameters key (`interfaceButtonParams`, the module switch): on a PolySynth track = overlay toggle (pads keep playing), otherwise the stock page; Shift + key = jump to the next PolySynth track (`nextSynthTrack`, wraps, cycles; own track last), select, strip page, open overlay; none: `no PolySynth` on the strip. Routing table and cycle: `seqplay::paramsKey` / `nextSynthTrack` (`test_params_key`). The earlier requests for a sample / MIDI compact overlay and for a Shift escape hatch were withdrawn by the owner (nothing of them is in the code).
- **Legend (owner: tap toggle, no long press).** Tapping the screen button of the already selected track toggles the pad legend at the release; hold + wheel is still the type list and never toggles; the wheel closes a shown legend; selecting another track, leaving Play mode, opening the overlay or a popup closes it. Strip hint `tap: help`, caption `tap track again to close` (the legend panel grew 14 px upwards for it). `test_hold_legend_flow` replays the keys driver's events (press, hold events at 333 / 233 / 143 ms ..., release).
- **Why the v0.3.2 Shift legend never showed on the device (code reading, not reproduced; there is no hardware here).** (1) An **Off** track never gets a legend (`viewKind`, `typeOff`) and Off is the state of every new track: a first try on a fresh project shows nothing at all. (2) Shift is the stock mute gesture: the stock `functShift` runs on every press (`showMuteButtons`, `setMuteFunct`, `display.synchronizeRefresh()` for the 8 labels) and its release runs `refreshEditState` -> `refreshActualActionButtonPage`, i.e. a stock redraw happens in the same instants in which our control is shown; the overlay's `refreshView` only repaints the control when its data changed, so a stock refresh in between could leave it hidden. Not confirmed. (3) The 250 ms gate also needed no screen button press in between. The tap toggle avoids all of it: the screen button presses are taken by the overlay (the stock handler never runs), the same path as the type list, and no Shift is involved. Still true: **an Off track has no legend** (pick a type first); check that first on the device if the legend does not show.

**Note band and voices (owner).** `Engine::soundingNotes(track)` copies the track's existing 128-bit sounding mask (no new audio-side work); `seqnotes::fillBand` folds it to 12 pitch classes plus a note list (at most 11 characters + ` +n`), read at most every 33 ms and only repainted when it changed; the band (12 keys y 405..419, names to the right) is drawn by the existing overlay control while nothing else is shown, x 292..700, clear of the edge markers; Strings marks its root. The PolySynth overlay's footer line shows the four voices (`Engine::voice(i)`: note, stage, envelope; `~` = releasing, bar = envelope level); idle voices are blank; the "newer file" notice replaces the row. "Stolen" is not shown (the engine does not keep that state). Not done: the dot per strip cell, root / scale of the other sequencer types. Budget: PolySynth overlay worst case 3592 bytes (limit 3600, with all marks, a running morph, four voices), note band worst 260 bytes (limit 600).

**Velocity: live vs recorded.** Cause of "the sequencers are too loud, recorded they sound right": the recorder stores a step volume only when the stock record option includes velocity (`recVelocity()`); otherwise the recorded step has volume -1 = the instrument's own default (`sendNoteOn`: `step->volume == -1`), but a live note was always played with `velocityToVolume(generator velocity)` (about 79 for the default velocity 100, up to 100). Fix in `Engine::onEvent` (Chord/Arp, Mono, the HYPER_RASP scripts and Strings all end in this function): `liveVolume(volume, recParams().velocity)` = -1 without the option. With the option both use the same value (a chord step stores the loudest note, live chord notes keep their own). `test_live_velocity_matches_recorded` (Chord/Arp and Strings, option on / off: live volumes, recorded ops and the mapping agree; it fails on the old code). Mono and the scripts are covered by the shared path, not by their own pad scenario.

**Sidechain and limiter (analysis, no code change).** The stock limiter (`AudioEffectLimiter`, one per side) takes the **whole mix** on input 0 (tracksAndSends mixer) and the sidechain source on input 1 (mux of the voice amplifiers 0-7, line inputs 8 / 9, synth parts 10+); with the sidechain on it ducks input 0 by the source level and blends the source in (`gain * delayed main + (1 - gain) * sidechain`). The PolySynth dry output is on the tracks mixer and its sends on the reverb / delay pre-mixers, all of which end in the tracksAndSends mixer, so it is **limited and ducked exactly like a sample track** (the source, e.g. a kick track, ducks it). Missing blocks (an idle engine allocates none) are already treated as silence by the mixers and the limiter. Not a source: the mux has fixed inputs per sample voice, a PolySynth track has no voice amplifier, and the project setting lists tracks; adding it needs a new mux input, a tap of the PolySynth bus and a list entry (a later plan). A track that plays the PolySynth instrument selected as source gives silence.
